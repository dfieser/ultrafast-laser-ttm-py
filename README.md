# laserttm — Ultrafast Laser TTM Toolbox (Python)

Python port of the [Ultrafast Laser TTM Toolbox](https://github.com/dfieser/ultrafast-laser-ttm-toolbox),
the MATLAB reference implementation for:

> Fieser, D., Dewanjee, U. N., and Hu, A. (2026). *A Computationally Efficient
> Two-Stage Two-Temperature Model for Multi-pulse Femtosecond Laser Heat
> Accumulation in Tungsten*. Journal of Materials Engineering and Performance.
> [doi:10.1007/s11665-026-14738-6](https://doi.org/10.1007/s11665-026-14738-6)

Two-temperature model (TTM) solvers for ultrafast pulsed-laser heating of
metals: single-pulse electron–lattice dynamics on femtosecond timescales,
heat accumulation over thousands of pulses, and moving-beam scans, using the
paper's two-stage strategy (stiff coupled TTM solve during the pulse and
relaxation, Crank–Nicolson diffusion between pulses). NumPy + SciPy, with
Numba-compiled kernels on the hot loops — no MATLAB required.

**All six solvers are ported and numerically validated** against golden
fixtures generated by the MATLAB reference implementation (see
[Validation](#validation-against-the-matlab-reference)). The MATLAB
repository remains the reference implementation described in the paper.

## Installation

Requires Python ≥ 3.10.

```bash
git clone https://github.com/dfieser/ultrafast-laser-ttm-py.git
cd ultrafast-laser-ttm-py
pip install -e .          # add ".[dev]" for pytest + ruff
```

The first solver call in a fresh environment takes a little longer while
Numba compiles the kernels; compiled kernels are cached on disk after that.

## Quick start

```python
from laserttm import surface_point_solver

cfg = {
    "material": "W",           # tungsten preset ('Cu', 'Au', 'Al', 'custom')
    "Pavg": 10,                # average power [W]
    "spotRadius": 100e-6,      # 1/e^2 spot radius [m]
    "f_rep": 5e6,              # repetition rate [Hz]
    "tau_FWHM": 500e-15,       # pulse width, FWHM [s]
}
cfg["simDuration"] = 50 / cfg["f_rep"]   # simulate 50 pulses

results = surface_point_solver(cfg)
print(results["peakTe_C"], results["finalResid_C"])
```

Config dicts use the same field names, defaults, and semantics as the MATLAB
`cfg` structs, and every solver returns the same v1 result contract
(`solver`, `solverId`, `contractVersion`, `material`, `outputFile`,
`outputDir`, `inputConfig`, plus `nPulses` and `wallTime_s` where
meaningful), so studies scripted against the MATLAB toolbox translate
directly. Every run writes its text output under `outputs/` (or
`cfg["outputDir"]`).

Runnable baseline scripts for each solver live in [examples/](examples/),
mirroring the MATLAB `examples/` scripts one-to-one.

## Solvers

| Solver | Entry point | What it computes |
| --- | --- | --- |
| Surface point | `surface_point_solver(cfg)` | 0D electron and lattice temperatures at the surface, with inter-pulse depth diffusion |
| Depth profile | `depth_profile_solver(cfg)` | 1D depth-resolved Te(z,t) and Tl(z,t), per-pulse peaks, inversion metrics |
| Radial profile | `radial_profile_solver(cfg)` | radial surface temperature under a Gaussian spot ('scale' and 'independent' modes) |
| Single pulse | `single_pulse_visualizer(cfg)` | one pulse with spatial snapshots at chosen delays |
| Inversion analysis | `inversion_quantifier(cfg)` | per-pulse inversion magnitude, onset, and duration statistics |
| Scanning beam | `scanning_beam_solver(params, output_dir, save_plots)` | 2D surface temperature under a moving beam |

Each is a line-faithful port of the corresponding MATLAB solver, including
the console report, text output files, and figure set (matplotlib).

## Validation against the MATLAB reference

`validation/fixtures/` holds golden fixtures produced by running every
solver in MATLAB R2026a (`validation/generate_fixtures.m`) at fixed
configurations, including the MATLAB repo's baseline examples. The test
suite re-runs each configuration in Python and asserts agreement:

- Solvers built on the hand-rolled, step-identical kernels (surface point,
  radial profile, scanning beam) agree to round-off: relative errors of
  ~1e-15, and at most 1.6e-10 K across a 36,000-pulse scan.
- Solvers built on a stiff integrator (depth profile, single pulse,
  inversion quantifier) run MATLAB `ode15s` vs SciPy `BDF` — same solver
  family at the same tolerances — and agree at integrator-tolerance level
  (relative errors ~1e-4 on peak temperatures).

```bash
python -m pytest             # fast suite (~1 min)
python -m pytest -m slow     # + the 36,000-pulse scanning baseline (~9 min)
python validation/benchmark.py   # wall-time comparison vs MATLAB
```

## Performance

Warm-run wall times on the same machine (MATLAB times recorded when the
fixtures were generated; details in `validation/fixtures/manifest.json`):

| Case | MATLAB | Python | Speedup |
| --- | ---: | ---: | ---: |
| surface_point_baseline (50 pulses) | 7.11 s | 0.07 s | 108× |
| single_pulse_baseline | 1.36 s | 0.04 s | 32× |
| radial_profile_baseline (100 pulses) | 1.41 s | 0.10 s | 15× |
| depth_profile_baseline (100 pulses) | 17.60 s | 12.9 s | 1.4× |
| scanning_small (3,600 pulses) | 29.96 s | 22.9 s | 1.3× |
| scanning_baseline (36,000 pulses) | 927.2 s | 543.6 s | 1.7× |
| inversion_baseline (20 pulses) | 4.35 s | 6.1 s | 0.7× |

The depth-solver family currently mirrors the MATLAB integration windows
exactly; relaxing the step cap outside the source window (the source is
identically zero beyond 10·τ from each pulse center) is a planned
optimization for the stiff phase.

## Relationship to the MATLAB toolbox

- The [MATLAB repo](https://github.com/dfieser/ultrafast-laser-ttm-toolbox)
  is kept stable for reproducibility of the published work.
- This package is the actively developed implementation going forward.
- Solver configs and the v1 result contract are preserved field-for-field
  where practical.
